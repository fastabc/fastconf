# FastConf 可复现性能比较（2026-10-24）

本次使用当前工作树重新测量，覆盖启动、重载、热读和诊断成本。FastConf 热读零分配，
但各库的启动和发布成本不同；下表只比较固定适配方式与输入，不能推导所有应用、
格式或数据结构的性能排序。

## 测量范围

- Apple M5 Pro，Darwin 27.0.0 / arm64，Go 1.26.10，GOMAXPROCS=4，GOGC=100。
- FastConf：`0a7b78e` 基线加本次云 Provider / Notifier 工作树；测量时完整源码校验和见 `source-sha256.txt`。报告和 README 在测量后更新。
- Viper 1.21.0、Koanf 2.3.0、Cleanenv 1.5.0、Envconfig 1.4.0；完整依赖由独立 go.mod/go.sum 固定。
- 68 组 benchmark，每组 10 次、benchtime=1s，共 680 行样本。下表均为十次中位数；benchstat 的区间与离散程度保存在 summary.txt。
- 27 个独立进程各记录 100 次重载，共 2700 条延迟样本；分别记录进程峰值 RSS。
- 比较适配器先单独通过 race 检查。计时期间未并行运行本次任务的构建、race 或其他检查；操作系统及其他应用仍可能产生调度噪声。

2026-10-18 的旧报告使用 Go 1.26.9、5 次 × 200ms；本次工具链、源码和采样参数不同，
不能将两次数字之差直接归因于某项代码变更。亚纳秒热读是紧循环吞吐量，不能当作
一次业务请求的延迟保证；部署决策应在目标环境复测。

## 运行时重载

Viper/Koanf 适配器也执行解码、相同校验、JSON 哈希去重及 atomic.Pointer 发布，
相关代码完全公开。每次候选使用新解析器，避免残留旧键。FastConf 用可更新的内存
Provider，因此这里没有文件输入指纹的快速跳过。单位：毫秒/次。

| 64KiB | 校验拒绝 | 1.5474 | 1.4570 | 1.8793 |

## 独立延迟与峰值内存

以下为有效重载的独立进程测量，单位为毫秒和 MiB。RSS 来自 Darwin time -l，
包含运行时、构造三份 fixture、解析器及加载状态；不是单快照大小。p95/p99 从
100 条原始延迟按 nearest-rank 计算，没有从 ns/op 推导。首次加载后执行一次 GC，
没有额外预热循环；小样本可能受到调度及缓存建立影响。

|---|---|---:|---:|---:|---:|

| 4 KiB | Viper | 0.1144 | 0.1895 | 0.3284 | 16.84 |

## FastConf 诊断与历史成本

| 输入 | 操作 | ms/op | 分配 MiB/op |
|---|---|---:|---:|
| 4KiB | 已缓存视图的 Map 复制 | 0.0214 | 0.0536 |
| 4KiB | 有效重载 + history=8 + 冷 Map | 0.1645 | 0.1995 |
| 64KiB | 已缓存视图的 Map 复制 | 0.3399 | 0.8234 |
| 64KiB | 有效重载 + history=8 + 冷 Map | 2.2471 | 2.9751 |
| 1024KiB | 已缓存视图的 Map 复制 | 5.2762 | 13.1817 |
| 1024KiB | 有效重载 + history=8 + 冷 Map | 34.0966 | 48.6871 |

Map 返回调用方可修改的副本，因此已缓存视图也要分配。冷路径和历史测试包含完整
重载，不应把它的全部成本归于历史环。没有同等功能的竞品接口未进入该项比较。

文件读取测试统一使用 os.ReadFile，数据位于真实临时文件，操作系统缓存已热；
原始样本保存在本地 results/ 目录，不纳入 Git。并发测试固定 4 KiB、一个 1 ms ticker
写者及并行读者，检查 Counter=Mirror。ticker 请求频率不等于实际完成频率；分配
统计包含写者分配。

## 复现与原始证据

本次使用 Go 1.26.10，按顺序执行，避免 correctness 与计时并发：

```sh
cd benchmarks/compare
GOWORK=off go test -mod=readonly -race -count=1 ./...
COUNT=10 BENCHTIME=1s SAMPLES=100 bash run.sh results/2026-10-24
```

[适配器、范围与官方 API 来源](README.md)说明了比较契约。runner 生成原始 benchmark
（raw.txt）、benchstat 汇总（summary.txt）、环境记录（environment.txt）、依赖版本
（modules.txt）、fixture 校验和及一致性测试（correctness.txt）、测量时文件校验和
（source-sha256.txt），以及各组延迟 JSON 与 RSS 文件。

本次产物保存在本地 `results/2026-10-24/`；旧的 `results/2026-10-18/` 保留。
整个 results/ 目录均被 Git 忽略，克隆仓库后需重新运行命令生成原始测量产物。

没有测试多层目录、真实远程服务、Kubernetes 投射卷、跨机器或跨平台性能，也没有
复制所有生产校验、订阅、密钥处理成本。各方案的生产采用决策仍应以应用的实际
输入规模、变更频率和发布流程为准。
