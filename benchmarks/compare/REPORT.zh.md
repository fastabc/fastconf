# FastConf 可复现性能比较（2026-10-18）

本次数据支持“FastConf 热读零分配、提供完整发布流程”，不支持“所有操作最快”。
在本组单层 YAML 数据中，Viper 的启动加载中位数低于 FastConf；64 KiB / 1 MiB
有效重载的 FastConf 与 Viper 中位数接近。Cleanenv 的单纯启动解析成本较低。
这些是固定适配方式下的结果，不能推导出所有应用、格式或数据结构的排序。

## 测量范围

- Apple M5 Pro，Darwin 27.0.0 / arm64，Go 1.26.9，GOMAXPROCS=4，GOGC=100。
- FastConf：fdaaf6c 基线加本次 P0–P1 工作树实现。测量时源码校验和见 source-sha256.txt；报告和文档整理在测量后完成。
- Viper 1.21.0、Koanf 2.3.0、Cleanenv 1.5.0、Envconfig 1.4.0；完整依赖由独立 go.mod/go.sum 固定。
- 68 组 benchmark，每组 5 次、benchtime=200ms，共 340 行样本。下表均为五次中位数。
- 27 个独立进程各记录 100 次重载，共 2700 条延迟样本；分别记录进程峰值 RSS。
- 计时期间未并行运行本次工作的构建、race 或其他检查。操作系统及其他应用仍可能产生调度噪声。

五个重复样本不足以让 benchstat 给出默认 95% 非参数置信区间，summary.txt 保留了
相应提示。本报告不据此声称统计显著性；需要稳定容量规划时使用 runner 默认的
10 次、1s 参数并在目标机器复测。亚纳秒热读是紧循环吞吐量，不能当作一次业务
请求的延迟保证。

## 启动加载

内存中的 YAML → 新结构体 → 相同业务校验；FastConf 用 Load，没有后台 watcher。
Cleanenv 使用 ParseYAML，环境变量另测。单位：毫秒/次。

| 输入 | FastConf | Viper | Koanf | Cleanenv |
|---|---:|---:|---:|---:|
| 4KiB | 0.1092 | 0.0956 | 0.1227 | 0.0642 |
| 64KiB | 1.5834 | 1.4382 | 1.8815 | 0.9801 |
| 1024KiB | 25.4331 | 23.1214 | 31.2360 | 16.2825 |

## 运行时重载

Viper/Koanf 适配器也执行解码、相同校验、JSON 哈希去重及 atomic.Pointer 发布，
相关代码完全公开。每次候选使用新解析器，避免残留旧键。FastConf 用可更新的内存
Provider，因此这里没有文件输入指纹的快速跳过。单位：毫秒/次。

| 输入 | 操作 | FastConf | Viper + 发布适配器 | Koanf + 发布适配器 |
|---|---|---:|---:|---:|
| 4KiB | 有效更新 | 0.1124 | 0.1009 | 0.1281 |
| 4KiB | 相同值 | 0.1125 | 0.0990 | 0.1294 |
| 4KiB | 校验拒绝 | 0.1091 | 0.0966 | 0.1219 |
| 64KiB | 有效更新 | 1.6910 | 1.7010 | 1.9355 |
| 64KiB | 相同值 | 1.5864 | 1.5312 | 1.9334 |
| 64KiB | 校验拒绝 | 1.5375 | 1.4570 | 1.8961 |
| 1024KiB | 有效更新 | 25.2194 | 25.3336 | 32.9502 |
| 1024KiB | 相同值 | 25.7808 | 24.5885 | 33.0381 |
| 1024KiB | 校验拒绝 | 23.9215 | 23.8698 | 31.5160 |

有效更新始终同时改变 Counter 和 Mirror；无效更新保留原指针。列表项数量和其他
字段保持固定。noop 在这些 Provider 上仍经过解析及校验，不能拿此结果替代文件
输入指纹 shortcut 的测量。

|---|---:|---:|

纯环境变量启动读取时，FastConf 的来源装配及校验流水线有额外成本。该场景不需要

## 独立延迟与峰值内存

以下为有效重载的独立进程测量，单位为毫秒和 MiB。RSS 来自 Darwin time -l，
包含运行时、构造三份 fixture、解析器及加载状态；不是单快照大小。p95/p99 从
100 条原始延迟按 nearest-rank 计算，没有从 ns/op 推导。首次加载后执行一次 GC，
没有额外预热循环；小样本可能受到调度及缓存建立影响。

| 输入 | 实现 | p50 ms | p95 ms | p99 ms | 进程峰值 RSS MiB |
|---|---|---:|---:|---:|---:|
| 4 KiB | FastConf | 0.1928 | 0.3407 | 0.4275 | 17.16 |
| 4 KiB | Viper | 0.0972 | 0.1162 | 0.2454 | 16.95 |
| 4 KiB | Koanf | 0.1332 | 0.2189 | 0.3257 | 16.58 |
| 64 KiB | FastConf | 1.5830 | 1.7191 | 2.0467 | 18.75 |
| 64 KiB | Viper | 1.5641 | 1.7954 | 2.1691 | 18.11 |
| 64 KiB | Koanf | 1.9599 | 2.0817 | 2.1958 | 18.41 |
| 1024 KiB | FastConf | 24.7737 | 27.3079 | 27.9152 | 67.02 |
| 1024 KiB | Viper | 24.0823 | 28.1693 | 31.7622 | 72.94 |
| 1024 KiB | Koanf | 31.9424 | 37.5765 | 40.3065 | 69.61 |

noop 和非法重载的延迟/RSS 也保存在相同目录的 JSON 与 memory.txt 文件中。
p99 在 100 个样本中只对应第 99 个有序样本，不构成服务级尾延迟保证。

## FastConf 诊断与历史成本

| 输入 | 操作 | ms/op | 分配 MiB/op |
|---|---|---:|---:|
| 4KiB | 已缓存视图的 Map 复制 | 0.0212 | 0.0536 |
| 4KiB | 有效重载 + history=8 + 冷 Map | 0.1669 | 0.1996 |
| 64KiB | 已缓存视图的 Map 复制 | 0.3417 | 0.8234 |
| 64KiB | 有效重载 + history=8 + 冷 Map | 2.3080 | 2.9734 |
| 1024KiB | 已缓存视图的 Map 复制 | 5.3827 | 13.1817 |
| 1024KiB | 有效重载 + history=8 + 冷 Map | 33.9792 | 47.9191 |

Map 返回调用方可修改的副本，因此已缓存视图也要分配。冷路径和历史测试包含完整
重载，不应把它的全部成本归于历史环。没有同等功能的竞品接口未进入该项比较。

文件读取测试统一使用 os.ReadFile，数据位于真实临时文件，操作系统缓存已热；
原始样本保存在本地 results/ 目录，不纳入 Git。并发测试固定 4 KiB、一个 1 ms ticker 写者及并行读者，检查
Counter=Mirror。ticker 请求频率不等于实际完成频率；分配统计包含写者分配。

## 复现与原始证据

```sh
cd benchmarks/compare
GOWORK=off go test -race ./...
COUNT=5 BENCHTIME=200ms SAMPLES=100 bash run.sh results/local
```

- [适配器、范围与官方 API 来源](README.md)

以上命令在本地 `results/local/` 生成原始 benchmark（`raw.txt`）、benchstat
汇总（`summary.txt`）、环境记录（`environment.txt`）、依赖版本（`modules.txt`）、
fixture 校验和及一致性测试（`correctness.txt`）、测量时文件校验和
（`source-sha256.txt`），以及各组延迟 JSON 与 RSS 文件。
本次测量产物保存在本地 `results/2026-10-18/`；整个 `results/` 目录均被 Git 忽略，
克隆仓库后需运行上述命令重新生成测量产物。

没有测试多层目录、真实远程服务、Kubernetes 投射卷、跨机器或跨平台性能，也没有
复制所有生产校验、订阅、密钥处理成本。各方案的生产采用决策仍应以应用的实际
输入规模、变更频率和发布流程为准。
